## Verification

- All **41 tests passed with the existing scan reference fixtures**, including
  local OCR/searchable and image-only exports, image processing, ordering,
  original-file preservation and nine zoom/preview tests. The standard release
  invocation additionally passed 37 tests and skipped the four opt-in fixture
  tests, which had already passed in the explicit fixture run.
- Source-built SANE 1.4.0 + libusb 1.0.30 + libpng 1.6.59 + libjpeg-turbo 3.2.1;
  arm64, minimum OS 27.0, no non-system dynamic runtime libraries. Build tools:
  Xcode 27.2 (27B52), clang 21, macOS SDK 27.2.
- The signed release helper detected the connected P-208II over USB without
  starting the feeder. Actual 300-dpi duplex scan/quality tests took place
  during development; the release check did not perform a new paper scan.
- The app received its ticket before final ZIP creation. Strict app and helper
  signatures, Developer ID/Team, runtime/timestamps, empty entitlements,
  configuration, icon, license files, attached app ticket and Gatekeeper passed.
- `publish_release.sh --dry-run` passed. The exact four public assets were
  downloaded into a fresh directory and byte-compared with local files. All
  GitHub asset digests matched; the same complete ZIP/app/helper/ticket/source
  verifier passed again on the downloaded assets.
- Anonymous GitHub API access confirmed public visibility, default branch
  `main` and GPL detection. Real scan images and local evidence were excluded
  from Git; only the fictional printable test document is published.
- A real negative checksum test exposed system Bash 3.2's treatment of failed
  standalone `[[ … ]]` assertions. Explicit failure branches and a regression
  guard script now reject invalid versions/hashes before extraction or Apple
  submission. The first accepted build's evidence was retained locally; the
  final release was rebuilt and notarized from the corrected commit above.

## Boundaries

The user accepted the document/zoom preview before release. Only the P-208II
on the development M5/macOS 27.2.1 at 300 dpi was physically verified. Other
scanners, Intel, older macOS and color acquisition are unsupported. A separate
clean-Mac launch, 600-dpi acquisition and full 10-sheet batch remain untested.
This release evidence does not claim those checks. The current GUI automation
service also failed to return a fresh branding snapshot; bundle identity,
display name and icon were verified directly from the delivered app.

This documentation is added after publication without moving the release tag.
